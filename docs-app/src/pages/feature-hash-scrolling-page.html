Hash Scrolling

Link directly to content inside a routed view, including targets created by asynchronous route work.

Syntax

<a au-link="guide#api-reference">
  API reference
</a>

<a au-link.bind="{
  target: 'guide',
  options: { hash: 'api-reference' }
}">
  API reference
</a>

<au-route
  path="guide"
  loading.bind="() => prepareApi()">
  <section id="api-reference">...</section>
</au-route>

Both links generate the same URL. Use the compact target when the path and fragment are static. Use an au-link.bind instruction object when the target, hash, parameters, or matching options are dynamic.

Meaning

The hash remains route state while the pathname selects the route tree. After navigation succeeds, scrolling waits until every activating route view is attached, decodes the hash, and finds an element by id or anchor name.

Apply it

Routing.customize({
  scrolling: {
    behavior: 'smooth',
    block: 'start'
  }
});

The default browser adapter enables hash scrolling automatically. Use scrolling: false to disable it. Memory and custom adapters opt in with scrolling: true or an options object when they render into a browser document.

The same link becomes /guide#api-reference in path mode, #guide#api-reference in hash mode, and ?app=guide#api-reference in query mode.
