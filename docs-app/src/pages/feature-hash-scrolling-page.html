Scrolling & Restoration

Link to asynchronously rendered content, start new pages at the top, and return users to their saved position with browser history.

Syntax

<a au-link="guide#api-reference">
  API reference
</a>

<a au-link.bind="{
  target: 'guide',
  options: { hash: 'api-reference' }
}">
  API reference
</a>

<au-route
  path="guide"
  loading.bind="prepareApi()">
  <section id="api-reference">...</section>
</au-route>

Both links generate the same URL. Use the compact target when the path and fragment are static. Use an au-link.bind instruction object when the target, hash, parameters, or matching options are dynamic.

Meaning

The hash remains route state while the pathname selects the route tree. After navigation succeeds, scrolling waits until every activating route view is attached. Fragment selection follows HTML behavior: literal then decoded IDs, followed by legacy <a name> targets, with special handling for #top.

New push and replace navigations start at the top unless a hash selects a target. Back and Forward restore the position saved for that individual history entry after its routed view settles.

Apply it

Routing.customize({
  scrolling: {
    restoration: 'restore',
    behavior: 'smooth',
    block: 'start'
  }
});

Every automatic action waits for the routed view tree to settle. Set hash: false to keep the selected restoration policy while disabling only hash-target scrolling.

The default browser adapter enables scrolling automatically and temporarily sets native history.scrollRestoration to manual while active. Use scrolling: false to disable it. Memory and custom adapters opt in with scrolling: true or an options object when they render into a browser document.

The same link becomes /guide#api-reference in path mode, #guide#api-reference in hash mode, and ?app=guide#api-reference in query mode.
