Routing Adapters

Keep the route tree independent from browser history with an injectable location boundary.

What an adapter changes

An adapter is the boundary between the route tree and its host location. It decides where the current route is read, how au-link formats an href, where programmatic navigation is stored, and which host navigation events enter the router.

It does not change route matching, parameters, nesting, fallback behavior, swap order, or view rendering. The same au-route templates work with every adapter.

Choose an adapter

ChoiceWhat it providesUse it for
Default browser adapterPathname, hash, or query-key URLs plus optional anchor interceptionNormal browser applications
MemoryPathAdapterAn in-process history stack with no browser globalsTests, SSR setup, previews, workers, and non-browser hosts
Custom IPathAdapterApplication-defined storage, formatting, and external navigation eventsWebViews, native shells, micro-frontends, or custom URL policies

If no custom adapter is configured, Router HTML creates the browser adapter and applies routingMode, routeQueryKey, and interceptLinks. Supplying a custom adapter skips IWindow resolution; that adapter owns its URL and click policy.

The adapter contract

interface IPathAdapter {
  getCurrentPath(): string;
  formatHref(path: string): string;
  push(path: string): void;
  replace(path: string): void;
  subscribe(callback: (path: string) => void): () => void;
}
MethodResponsibility
getCurrentPath()Return the complete internal route location used when the coordinator starts or restarts.
formatHref()Convert an internal route into the href format exposed by au-link.
push()Store a new location requested through au-link or $route.load(). Do not notify the subscription again; the route tree already applies that navigation.
replace()Replace the current stored location without creating another history entry.
subscribe()Report navigation initiated outside the route context, such as browser Back, Forward, plain intercepted anchors, or native-host messages.

The coordinator subscribes during start(), unsubscribes during stop(), and creates a fresh subscription after restart. Adapter teardown must therefore be safe to call once per subscription.

Pass an adapter instance

const adapter = new MemoryPathAdapter('/dashboard');

void Aurelia
  .register(Routing.customize({
    adapter,
    animations: false
  }))
  .app({ host, component: App })
  .start();

This is the smallest setup when the application creates and owns the adapter. The same instance is registered as IPathAdapter for injection into application code.

Resolve an adapter through DI

void Aurelia
  .register(
    Registration.singleton(MyPathAdapter, MyPathAdapter),
    Routing.customize({ adapter: MyPathAdapter })
  )
  .app({ host, component: App })
  .start();

// A pre-registered IPathAdapter is selected automatically.
void Aurelia.register(
  Registration.singleton(IPathAdapter, MyPathAdapter),
  Routing
);

Use a DI key when the adapter has injected dependencies or a lifecycle shared with other services. Registering IPathAdapter directly also works without an adapter option.

Create an adapter with a factory

Routing.customize({
  adapterFactory: container => new NativeShellAdapter(
    container.get(NativeNavigationBridge)
  )
});

The factory receives the application container. Use it when construction needs runtime values or cannot be expressed as a normal DI registration. Supplying both adapter and adapterFactory is rejected.

Use memory history

<nav>
  <a au-link="dashboard">Dashboard</a>
  <a au-link="reports">Reports</a>
</nav>
const adapter = new MemoryPathAdapter('/dashboard');

adapter.back();    // restores the previous route
adapter.forward(); // restores the next route
adapter.go(-2);    // moves through memory history

au-link asks its local route context to resolve and load the target, so application code does not need the coordinator. The coordinator stores the resolved location through push() or replace(). Adapter back(), forward(), and go() represent history movement originating from the host and notify the route tree.

Options with custom adapters

OptionWith a custom adapter
routingModeIgnored by Router HTML; implement the required formatting in the adapter.
routeQueryKeyUsed only by the default browser query adapter.
interceptLinksUsed only by the default browser adapter. A custom host decides how navigation events enter subscribe().
swapOrderStill applies because it controls route views rather than location storage.
animationsStill applies because it controls route views rather than location storage.
