Loading & Loaded

Prepare a route before its template appears, then respond when its complete nested branch is ready.

Syntax

<au-route
  path="products/:id"
  loading.bind="() => loadProduct()"
  loaded.bind="() => productIsReady()">
  <h1>${product.name}</h1>
</au-route>

Use Aurelia v2 function bindings for both callbacks. The arrow function retains the surrounding binding context; the removed .call command is neither needed nor supported.

Meaning

loading runs before the route template activates and waits for a returned promise. loaded runs after the template and its asynchronous Aurelia activation lifecycle are ready.

Nested branches load from parent to child and report loaded from child to parent. This lets a parent prepare shared data first while its loaded callback observes a complete child branch.

Apply it

export class App {
  public async loadProduct(): Promise<void> {
    this.product = await this.products.getCurrent();
  }

  public productIsReady(): void {
    this.analytics.pageReady('product');
  }
}

Return nothing for synchronous work. Return a promise only when activation must wait, keeping ordinary routes on the synchronous path.

Loading errors today

A thrown error or rejected loading promise prevents that route view from activating, and its loaded callback does not run. Handle expected data failures inside the callback when the page should present a recoverable error state.

The navigation transaction keeps the outgoing URL and view available while loading is pending. A rejected loading callback discards the incoming branch, restores route state, and rejects programmatic navigation with the original error.
