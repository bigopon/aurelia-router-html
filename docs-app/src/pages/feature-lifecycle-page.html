Loading & Loaded

Prepare a route before its template appears, then respond when its complete nested branch is ready.

Syntax

<au-route
  path="products/:id"
  loading.bind="loadProduct($lifecycle)"
  loaded.bind="productIsReady()">
  <h1>${$route.data.loading.name}</h1>
</au-route>

The router evaluates each Aurelia expression once at its lifecycle phase, in the route's live binding scope. Use $lifecycle when the expression needs route state, prior data, or the abort signal.

Meaning

loading runs before the route template activates and waits for a returned promise. loaded runs after the template and its asynchronous Aurelia activation lifecycle are ready.

Nested branches load from parent to child and report loaded from child to parent. This lets a parent prepare shared data first while its loaded callback observes a complete child branch.

The fulfilled return values are available as $route.data.loading and $route.data.loaded. The router does not cache them: applications decide whether to reuse context.previousData, a service cache, or a fresh request.

Apply it

export class App {
  public loadProduct(context: RouteLifecycleContext) {
    return this.products.get(context.params.id, context.signal);
  }

  public productIsReady() {
    return this.analytics.pageReady('product');
  }
}

The lifecycle context includes the route, params, query, hash, abort signal, and prior lifecycle results. Return any value or promise; activation still waits only for promises.

Loading errors today

A thrown error or rejected loading promise prevents that route view from activating, and its loaded callback does not run. Handle expected data failures inside the callback when the page should present a recoverable error state.

The navigation transaction keeps the outgoing URL and view available while loading is pending. A rejected loading callback discards the incoming branch, restores route state, and rejects programmatic navigation with the original error.

Cancelled and unhandled failed navigations restore $route.data to its pre-navigation values. When an error boundary locally recovers by replacing a failed subtree with a sibling fallback, that failed route context may retain its last fulfilled lifecycle result. This is route state for previousData, not router-managed caching; applications must not rely on local recovery to clear it.
