Route Groups

Use a structural au-route when several descendants should share markup or behavior without owning a URL segment.

Syntax

<au-route group>
  <section class="shell">
    <h3>Catalog</h3>
    <au-viewport></au-viewport>
  </section>

  <au-route path="/" exact>Browse</au-route>
  <au-route path="details/:id">Details</au-route>
</au-route>

Meaning

group makes an au-route structural instead of path-owning. It contributes no path segment, cannot be linked to directly, and becomes active only when one of its descendant routes matches.

A group may contain ordinary markup, bindings, slots, and child components in addition to nested au-route declarations. It is not restricted to route elements only.

Keep group by itself. It does not combine with path, exact, fallback, or redirect-to.

Usage: Share layout without a path segment

<au-route group>
  <section class="catalog-shell">
    <aside>Filters</aside>
    <main>
      <au-route path="/" exact>Browse</au-route>
      <au-route path="details/:id" exact>Details</au-route>
    </main>
  </section>
</au-route>

The shell appears only while one of the grouped descendants is active, but the URL remains / or /details/:id rather than gaining an extra wrapper segment.

Usage: Apply one policy to a branch

<au-route
  group
  loading.bind="loadWorkspace($lifecycle)"
  can-load.bind="transition => canOpenWorkspace(transition)">
  <workspace-chrome></workspace-chrome>

  <au-route path="projects" exact>Projects</au-route>
  <au-route path="reports" exact>Reports</au-route>
</au-route>

Put branch-wide lifecycle or guard behavior on the group when multiple descendants should share the same preparation, authorization, or error boundary.

Usage: Organize descendants that would otherwise be sibling clutter

<au-route path="account">
  <h1>Account</h1>

  <au-route group>
    <account-tabs></account-tabs>
    <au-route path="/" exact>Profile</au-route>
    <au-route path="security" exact>Security</au-route>
  </au-route>

  <au-route path="billing" exact>Billing</au-route>
</au-route>

Use a group when some descendants belong to a shared sub-layout or concept, but introducing another path segment would be artificial.

Navigation implications

<a au-link="projects">Projects</a>
<a au-link="reports">Reports</a>
<!-- A group has no path, so links target one of its descendants instead. -->

Navigate to a descendant route, not to the group itself. Registered URLs come from the group's descendants, because the group is structural rather than addressable.
