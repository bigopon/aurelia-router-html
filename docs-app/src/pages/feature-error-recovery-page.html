Error Recovery

Turn a failed route into contextual fallback UI while keeping the accepted parent, requested URL, and diagnostic error available.

Syntax

<au-route
  path="reports"
  loading.bind="loadReports()"
  on-error.bind="failure => recover(failure)">
  <reports-panel></reports-panel>
</au-route>

<au-route path="*" fallback>
  ${$route.parent.failure.error.message}
</au-route>
import type {
  RouteErrorResult,
  RouteFailure
} from 'aurelia-router-html';

export class MyComponent {
  recover(
    failure: RouteFailure
  ): RouteErrorResult {
    console.error(failure.phase, failure.error);
    return { recover: 'local' };
  }
}

Meaning

on-error.bind is a route boundary callback. Failures travel from the route that threw toward its ancestors until a callback handles them. Returning nothing continues propagation; returning a redirect changes route; returning { recover: 'local' } rematches only the failed route's immediate parent.

Failure ownership

failure.source is the route that failed, failure.boundary is the route whose callback handled it, and failure.recovery is the failed route's immediate parent. That recovery context owns $route.failure. A sibling fallback therefore reads $route.parent.failure.

Phases

failure.phase identifies can-load, loading, view activation, or loaded. Unhandled errors retain atomic rollback and reject programmatic navigation with the original error.

Apply it

Handle domain-specific failures near their source, let a parent own section-level fallback UI, and reserve a grandparent boundary for application-area policy. The three examples below isolate each placement so the ownership difference stays visible.

Route handles its own failure

The failing route declares on-error.bind. Local recovery excludes that route and selects its sibling fallback.

Parent handles a child failure

The reports route only declares its loading work. Its workspace parent owns the boundary and the fallback presentation.

Grandparent handles a grandchild failure

The failure passes through a workspace with no handler before the portal boundary accepts it. Recovery still rematches at the failed route's immediate parent.
