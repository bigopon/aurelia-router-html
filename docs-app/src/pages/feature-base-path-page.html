Base Path Hosting

Deploy below the origin root without adding the hosting folder to route declarations, links, parameters, or redirects.

How Router HTML chooses the base

PrioritySourceResult
1Explicit basePathAlways wins, including when the document has a <base> element.
2Same-origin <base href>Used when basePath is omitted.
3No configured or document baseRoutes are hosted from /.

The base belongs to the browser adapter. Internally, the route tree continues to see paths such as /products, never /my-app/products.

Root-hosted application

No base configuration is needed when the application owns the origin root.

Aurelia
  .register(Routing)
  .app({ host, component: App })
  .start();
<a au-link="/products">Products</a>
<au-route path="products">...</au-route>

Both the browser URL and internal route are /products.

Derive the mount from HTML

The HTML <base> element defines how the browser resolves relative URLs throughout the document. In an Aurelia application it can also be the single source for the router mount.

<head>
  <base href="/my-app/">
</head>
// No basePath is needed.
Aurelia
  .register(Routing)
  .app({ host, component: App })
  .start();
au-link="/products"/my-app/products
href="products"/my-app/products, resolved natively by the browser
Internal route/products

Use this form when the same directory is the base for application routes and document-relative resources.

Configure the mount explicitly

Use basePath when routing needs an explicit deployment contract or the document cannot declare a base element.

Aurelia
  .register(Routing.customize({
    basePath: '/my-app'
  }))
  .app({ host, component: App })
  .start();

The trailing slash is optional. Router HTML normalizes /my-app and /my-app/ to the same mount.

Override an unrelated document base

Some hosts use <base> for document-relative assets rather than application routing. An explicit router base keeps those concerns separate.

<head>
  <base href="/assets/">
</head>
Routing.customize({
  basePath: '/my-app'
});
au-link="/products"/my-app/products
href="products"/assets/products, because native relative URLs still follow HTML <base>

Prefer au-link or root-qualified native anchors when the document base and router base intentionally differ.

Combine a base with each URL mode

Routing.customize({
  basePath: '/my-app',
  routingMode: 'path' // or 'hash' or 'query'
});
ModeInternal routeBrowser URL
Path/products/my-app/products
Hash/products/my-app/#products
Query/products/my-app/?app=products

Align the build and the router

A build tool's public base controls emitted asset URLs. Router HTML's basePath controls application locations. Subdirectory deployments commonly give them the same value, but they remain independent settings.

// vite.config.ts
export default defineConfig({
  base: '/my-app/'
});
// main.ts
Routing.customize({
  basePath: '/my-app'
});

The production server must also return the application entry document for deep requests such as /my-app/products. A router base cannot replace the host's SPA fallback or rewrite rule.

Boundaries and validation

Document base discovery

Document atBase elementRouter result
https://example.com<base href="/my-app/">Valid: derives /my-app.
https://example.com<base href="https://example.com/my-app/">Valid: the absolute URL has the same origin.
https://example.com<base href="https://cdn.example.com/assets/">Ignored: browser history cannot route into another origin.

A cross-origin base can still control native relative assets and anchors. Router HTML simply does not treat its pathname as the application mount.

Explicit base paths

// Valid pathname-only values
Routing.customize({ basePath: '/my-app' });
Routing.customize({ basePath: '/my-app/' });
Routing.customize({ basePath: '/' });

// Invalid: query and fragment state do not belong to the mount path
Routing.customize({ basePath: '/my-app?tenant=one' });
Routing.customize({ basePath: '/my-app#shell' });

The invalid forms throw during router registration. Query and fragment values belong to navigation targets, not the deployment prefix.

Plain-link interception

<!-- With basePath: '/my-app' -->

<!-- Valid internal URL: intercepted when interceptLinks is enabled. -->
<a href="/my-app/products">Products</a>

<!-- Outside the mount: left to normal browser navigation. -->
<a href="/other-app/products">Other application</a>

<!-- Different origin: always left to normal browser navigation. -->
<a href="https://store.example.net/products">External store</a>

au-link="/products" remains root-absolute inside the application and generates /my-app/products after browser formatting.
