Basic Routes

See how fixed URL paths map directly to the content visitors expect.

Syntax

<au-route path="products">...</au-route>
<au-route path="./products">...</au-route>
<au-route path="/" exact>Index</au-route>

Meaning

Every au-route declaration matches the URL remaining from its parent. products and ./products mean the same contextual route. The zero-segment patterns /, ., and ./ match without consuming a segment, so they can act as an index with exact or as a prefix that keeps matching children.

A leading slash does not make an au-route declaration root-absolute. Prefer the slash-free form so declarations and navigation targets remain visually distinct.

Apply it

<!-- A native anchor needs a complete browser URL. -->
<a
  href="/help"
  class.bind="$route.isActive('/help', {}, { exact: true })
    ? 'is-active'
    : ''">
  Root help
</a>

<!-- au-link accepts a registered route target. -->
<au-route path="products">
  <a au-link="reviews">Local reviews</a>
  <a au-link="./reviews">Local reviews</a>
  <a au-link="/help">Root help</a>

  <au-route path="reviews">...</au-route>
</au-route>

A native <a href> uses the URL exactly as written, so bind $route.isActive() when it needs selected feedback. au-link resolves a registered route target and performs that active-state work automatically.

For route-link targets, reviews and ./reviews resolve from the current route context, while /help starts from the root context.

Use path="/" exact when you need the true index child. Omit exact only when the route should also stay active while one of its descendants owns the remaining segments.
