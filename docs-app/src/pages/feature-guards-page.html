Navigation Guards

Keep authorization and unsaved-work decisions beside the route whose navigation they control.

Syntax

<au-route
  path="account/:id"
  transition-on="params"
  transition-plan="rerun"
  can-load.bind="transition => canOpenAccount(transition)"
  can-unload.bind="() => canLeaveAccount()">
  <h1>Account</h1>
</au-route>

Guards use Aurelia v2 function bindings, retaining the surrounding binding context without .call.

Meaning

can-load approves, cancels, or redirects entry and selected matched-route transitions. can-unload approves or cancels leaving an active route, including a replace transition that recreates its view.

Outgoing guards run from the deepest active child upward. Incoming routes are discovered progressively: each route runs can-load, then loading, before its template reveals the next child. Loaded notification returns from child to parent.

For matched routes, replacement can-unload guards run deepest-first, then every affected guard on an already-declared route approves before selected routes begin loading or change their views. Descendants created inside a fresh replacement run their entry guards during candidate activation, and any denial still rolls back the replacement. can-load receives the same lifecycle context as loading, including kind, immutable from, to, and changes values, and the abort signal.

Apply it

public canOpenAccount(_transition: RouteLifecycleContext): boolean | string {
  return this.session.isSignedIn
    ? true
    : '/sign-in';
}

public canLeaveAccount(): boolean {
  return !this.form.isDirty
    || confirm('Discard your changes?');
}

Return true to continue, false to keep the complete current navigation, or a route target from can-load to redirect. A target without a leading slash resolves from the guarded route's parent; a leading slash starts at the root.

can-unload does not redirect. It either allows the current navigation to continue or returns false to keep the active branch and URL as they are.

Relative can-load redirects

<au-route path="area">
  <au-route path="workspace">
    <au-route
      path="private"
      exact
      can-load.bind="() => openPrivate()">
      Private
    </au-route>
  </au-route>

  <au-route path="login" exact>Login</au-route>
</au-route>
public openPrivate(): string {
  return '../login?from=private#warning';
}

The guard result uses the same target rules as au-link and declarative redirects. Here ../login?from=private#warning climbs from the guarded route's parent branch and settles at /area/login?from=private#warning.

Atomic navigation

The outgoing branch remains mounted and browser history remains unchanged while asynchronous guards and loading work are pending. Cancellation restores the outgoing route state; loading errors reject programmatic navigation with their original error.

Back and Forward move the browser first. If a guard denies that traversal, the adapter restores the prior history cursor without replacing either entry, preserving the complete forward/back stack.

The transition argument exposes an AbortSignal for application work that should stop when a newer navigation supersedes the current attempt.
