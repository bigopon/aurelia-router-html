Focus Management

Move keyboard users into newly rendered route content without stealing focus on initial loading or background URL-state updates.

Syntax

<au-route path="account" exact>
  <main>
    <h1 au-route-focus>Account settings</h1>
    <p>Manage your profile and security settings.</p>
  </main>
</au-route>

Add au-route-focus to the heading, region, or control that should receive focus when its route is newly attached.

Meaning

Focus waits for the complete routed view tree, including asynchronous activation. Initial rendering is ignored by default, and changing only query or hash state does not refocus an unchanged route. When nested incoming views provide markers, the last attached marker—normally the deepest route—wins.

Non-interactive targets such as headings receive tabindex="-1", making them programmatically focusable without adding them to the Tab order.

Apply it

Routing.customize({
  focus: {
    fallback: 'heading',
    initial: false,
    preventScroll: true
  }
});
OptionMeaning
focus: trueEnables explicit au-route-focus targets. Focus management is off by default.
fallback: 'none'Does nothing when the incoming route tree has no marked target. This is the default.
fallback: 'heading'Uses the first level-one heading inside <main> when no marked target attaches.
initial: trueAlso focuses after the application's initial route finishes. The default preserves the browser's initial focus.
preventScroll: falseAllows focusing to move the viewport. The default preserves the scroll result chosen by hash scrolling or restoration.
