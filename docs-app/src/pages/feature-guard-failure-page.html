Guard Failure Modes

Choose whether a denied route cancels the complete navigation or yields only its own subtree to local recovery UI.

Syntax

<au-route
  path="admin"
  can-load.bind="() => isAdmin()"
  guard-failure="local">
  <admin-panel></admin-panel>
</au-route>

<au-route path="*" fallback>
  <access-denied></access-denied>
</au-route>

Navigation failure

guard-failure="navigation" is the default. A false result cancels the complete transaction, preserving the previous URL, history entry, selected links, and rendered route tree.

Local failure

guard-failure="local" excludes the denied route and its descendants for the current transaction. Its immediate parent rematches the residue, approved ancestors commit, and a sibling fallback can render at the requested URL.

The exclusion expires after the transaction, so retries evaluate the guarded route again. Without a matching sibling, the approved parent commits with an empty child stage and development builds report a warning.

Scope

Local mode applies only when can-load returns false. Redirects remain redirects, exceptions use error recovery, and can-unload always protects the complete outgoing transaction.

Layered authorization

The example composes member, staff, and administrator checks through three nested levels. Each route renders contextual links beside its UI, local denial retains the approved parent, and the invocation log shows where evaluation stopped.
