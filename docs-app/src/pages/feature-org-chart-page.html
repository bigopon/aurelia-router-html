Example: Org Chart

Use nested route segments to grow a connected org chart one manager at a time while the same component keeps rendering each branch level.

Syntax

<au-route path="org/:employeeId">
  <org-node employee-id.bind="$params.employeeId"></org-node>
</au-route>

<!-- Inside org-node.html -->
<au-route repeat.for="report of reports" path.bind="report.id">
  <org-node employee-id.bind="report.id"></org-node>
</au-route>

Meaning

The outer route selects the current employee from the first dynamic segment. Each rendered node registers child routes for its direct reports, and those children point back to the same org-node component. The tree depth therefore comes from data, not from a fixed number of view-models.

The route remains the source of truth for the visible branch, so a copied URL can reopen the exact management chain someone is inspecting.

Apply it

Use this pattern for org charts, category trees, decision maps, workflow drill-downs, or any hierarchy where one segment chooses the next node and the same UI contract repeats.

Keep each node's component responsible for rendering its own card, the connected child choices, and the nested route outlet below that selection.

Why this works well here

<a
  repeat.for="report of reports"
  au-link.bind="report.id"
  active-class="selected">
  ${report.name}
</a>

Each child link is relative to the current node, so selecting a direct report appends exactly one more segment to the current branch. Active-state styling then highlights the chosen edge without reconstructing the whole URL manually.
