Segment Constraints

Keep URLs precise by allowing a named parameter to match only the shape of value that its route understands.

Syntax

<au-route path="products/:id{{^\d+$}}" exact>
  <h1>Product ${$params.id}</h1>
</au-route>

<au-route path="archive/:year{{^\d{4}$}}?" exact>
  <h1>Archive ${$params.year || 'all years'}</h1>
</au-route>

Place a regular expression inside {{ and }} after a named parameter. Keep ? at the end when the constrained parameter is optional.

Meaning

SyntaxMeaning
:id{{^\d+$}}Requires one segment containing digits only.
:period{{^(daily|weekly)$}}Requires one of the listed values.
:year{{^\d{4}$}}?Allows the segment to be absent, but requires four digits when supplied.
calendar/:date{{...}}/summaryConstrains a parameter in the middle of a path.

A constraint sees only its parameter's encoded segment between two / separators. It cannot consume another segment; use ** when a route intentionally owns the remaining path.

Regular expressions retain their normal JavaScript behavior. Add ^ and $ when the complete segment must match. Because Router HTML activates every matching regular sibling, overlapping constraints can activate together.

Apply it

<a au-link.bind="{
  target: '/products/:id{{^\\d+$}}',
  params: { id: product.id }
}">
  Open product
</a>

Generated links validate supplied values against the same constraint. A missing required value or a value that cannot match throws instead of producing an unusable URL.

Malformed expressions are reported when the route is created. If a path.bind, path.to-view, or :path value changes to an invalid constraint, the update throws and the previous valid matcher remains installed.
