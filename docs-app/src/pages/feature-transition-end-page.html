Transition End

Observe when a route transition has actually settled through a route-owned callback, without depending on template-root DOM events.

Current surface

<au-route
  path="details/:id"
  animate
  transition-end.bind="onTransitionEnd">
  ...
</au-route>

transition-end.bind is a route-level callback. It fires once per route transition, even when the route renders multiple root elements.

What it means

This is not the browser's raw transitionend event. It is the router's own transition-settlement signal for that route.

Internally, CSS-driven routes may still use browser transitionend and animationend events as completion sources, while callback-driven routes settle from the returned promise. transition-end.bind abstracts over those implementation details.

Callback shape

public onTransitionEnd = ({ direction, route, navigationId, animated }) => {
  console.log(direction, route.$path, navigationId, animated);
};

The callback receives the transition direction, the route context, the navigation id, and whether an animation path actually ran for that route.

Compared with loaded

loaded is a lifecycle/data signal. transition-end.bind is a visual transition settlement signal. A route can finish loaded before its transition settles.
