Query, Hash & URL Modes

Keep route matching focused on the pathname while query, fragment, and browser URL strategy remain explicit.

Syntax

<p>Sort: ${$query.get('sort')}</p>
<p>Section: ${$hash}</p>
<a href.bind="$route.href($route, {}, {
  query: { sort: 'price' },
  hash: 'reviews'
})">Price reviews</a>

Meaning

The pathname selects the route tree. Query values and the hash are exposed as $query and $hash without changing which route matches. The same values are available from $route.$query and $route.$hash.

These values always stay reactive. A matched route starts its configured transition-plan for them only when transition-on includes query or hash; parameter changes are selected by default. Use transition-plan="none" when reactive values alone are sufficient.

Apply it

Use path mode for normal server URLs, hash mode for static hosting, or query mode when the route must live under a reserved query key.

Routing.customize({
  routingMode: 'path'
});
// example.com/products/ice-cream/reviews

Routing.customize({
  routingMode: 'hash'
});
// example.com#products/ice-cream/reviews

Routing.customize({
  routingMode: 'query',
  routeQueryKey: 'app'
});
// example.com?app=products/ice-cream/reviews

Path mode with query and hash state

The pathname selects the product while query and hash values carry view state.

Hash-only routing

Generated links keep the complete route after #, making the example suitable for static hosts without rewrite rules.

Query-key routing

Generated links place the complete route under the configured app query key.
