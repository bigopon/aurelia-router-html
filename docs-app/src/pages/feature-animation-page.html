Animations

Opt routes into transition choreography today with CSS classes, and use this page as the staging area for the broader unified animate design.

Current surface

<au-route path="details" animate>
  ...
</au-route>

animate is now one route-level animation entry point. Bare animate preserves the existing CSS-class workflow, while string, callback, and object forms normalize into the same internal descriptor.

Implemented foundation

<au-route path="a" animate>
<au-route path="b" animate="fade">
<au-route path="c" animate.bind="animateRoute">
<au-route path="d" animate.bind="{ kind: 'css', name: 'fade' }">
<au-route path="e" animate.bind="{ kind: 'js', run: animateRoute }">

The implemented foundation is one route-level animate property with multiple value shapes. CSS remains the low-friction path; callback animation is the stronger primitive for exact completion and cancellation.

The broader design note currently lives in route-animation-design.md in the repository root.

Callback shape

public animateRoute = ({ direction, elements, signal }) => {
  const element = elements[0];
  if (element == null) return;

  const animation = element.animate(
    direction === 'enter'
      ? [{ opacity: 0, transform: 'translateY(18px)' }, { opacity: 1, transform: 'translateY(0)' }]
      : [{ opacity: 1, transform: 'translateY(0)' }, { opacity: 0, transform: 'translateY(-18px)' }],
    { duration: 180, easing: 'ease-out', fill: 'both' }
  );

  signal.addEventListener('abort', () => animation.cancel(), { once: true });
  return animation.finished.then(() => undefined, () => undefined);
};

Callback animation receives the route direction, animated elements, and an abort signal. Returning a promise gives the router an exact completion point, while superseding navigation aborts the stale callback path.

Reduced motion

@media (prefers-reduced-motion: reduce) {
  .animated-stage > .au-route-enter-active,
  .animated-stage > .au-route-leave-active {
    transition-duration: 1ms;
    transform: none;
  }
}

With the current CSS-based surface, reduced-motion support is expressed through ordinary CSS. If callback animation is added later, the callback context should expose the reduced-motion preference directly.
