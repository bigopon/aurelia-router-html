Relative Targets

Use URL-like targets consistently across au-link, redirects, href(), isActive(), and load().

Syntax

<a au-link="reviews">Reviews</a>
<a au-link="./reviews">Explicit descendant</a>
<a au-link="../specs">Parent sibling</a>
<a au-link="/products">Root route</a>
<a au-link="?page=2">Replace query only</a>
<a au-link="#comments">Replace hash only</a>

Meaning

TargetResult
reviews or ./reviewsResolve below the current route context.
../reviewsRemove one contextual URL segment, then resolve the sibling target.
Repeated ../Continue removing segments, but clamp at the route root instead of traversing above it.
/reviewsResolve from the root route context.
?page=2Keep the current pathname and replace only the query.
#commentsKeep the current pathname and query and replace only the hash.

Apply it

const href = this.route.href('../specs');
const queryOnly = this.route.href('?page=2');
const hashOnly = this.route.href('#comments');

await this.route.load('../../support');
await this.route.load('?sort=recent');
await this.route.load('#details');

The same target rules apply to declarative redirects. A redirect target like login?from=private#warning resolves from the redirect route's parent context and still carries its query and hash update in one step.

Parameterized parent traversal

const href = this.route.href('../compare/:otherId', {
  otherId: 'camera-pro'
});

const active = this.route.isActive('../compare/:otherId', {
  otherId: 'camera-pro'
}, { exact: true });

Relative targets can climb to an ancestor branch and still reuse active ancestor parameters. If the current route is /products/aster-pack/reviews, the href above becomes /products/aster-pack/compare/camera-pro.

Inside au-router

An au-router creates a new memory-backed route boundary. Relative targets still use the same rules, but they stay scoped to that nested router's current-path instead of affecting the outer browser route.
