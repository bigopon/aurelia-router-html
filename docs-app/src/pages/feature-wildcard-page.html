Wildcard Paths

Capture one dynamic segment or give a route ownership of every segment that remains.

Syntax

<au-route path="date/*/summary" exact>
  Date: ${$params['*']}
</au-route>

<au-route path="files/**">
  Path presented: ${$route.$path}
  Terminal segment: ${$params['**']}
  Residue after **: ${$route.residue}
  <au-route path="/" exact>Remaining URL is /</au-route>
</au-route>

Meaning

* consumes exactly one decoded segment wherever it appears in a pattern and exposes it as $params['*']. ** must be the final segment; it consumes the complete remaining path, exposes it as $params['**'], and gives nested routes the index residue /. A pattern can contain only one anonymous wildcard of each kind because each capture has one parameter key.

Apply it

<a au-link.bind="{
  target: 'date/*/summary',
  params: { '*': selectedDate }
}">
  Daily summary
</a>

<a au-link.bind="{
  target: 'files/**',
  params: { '**': filePath }
}">
  Open file
</a>

<au-route path="date/:date/summary/:category/errors">
  ...
</au-route>

Use * when exactly one segment varies and ** when the routed view owns an arbitrary-depth suffix. When multiple segments vary, give them names such as :date and :category. Captures are decoded and scoped to the route that declares them. Leading-slash forms /* and /** are equivalent to * and **.
