Why Router HTML

Describe the URL, navigation, nested layout, and rendered UI together in Aurelia templates—without maintaining a second route tree in TypeScript.

The route tree is the UI tree

Each route sits beside the markup it displays. Nesting in the template mirrors nesting in both the URL and the interface, so the complete feature is readable in one place.

<nav>
  <a au-link="products">Products</a>
  <a au-link="account">Account</a>
</nav>

<au-route path="products">
  <h1>Products</h1>
  <product-list></product-list>
</au-route>

<au-route path="account">
  <h1>Account</h1>

  <au-route path="profile">
    <profile-editor></profile-editor>
  </au-route>
</au-route>

Use the Aurelia template language you already know

Routes work with bindings, conditions, repeats, local template scope, and composed components. There is no parallel JavaScript route-configuration syntax to keep synchronized with the view.

<let active-tabs.bind="tabs.filter(tab => tab.enabled)"></let>

<template repeat.for="tab of activeTabs">
  <a au-link.bind="tab.path">
    ${tab.label}
  </a>

  <au-route path.bind="tab.path">
    <tab-panel tab.bind="tab"></tab-panel>
  </au-route>
</template>

Keep each concern in its natural home

ConcernWhere it lives
URL shape and nesting<au-route> in the template
Navigation and active feedbackau-link beside the interface it controls
Conditional and repeated route branchesStandard Aurelia template features
Data, permissions, and application stateView-models and services

Router HTML does not remove TypeScript from an Aurelia application. It removes the need to duplicate the application's route topology across JavaScript configuration and HTML views.

One routing mental model

A parent route consumes its part of the URL and gives the remainder to its children. The same route context resolves links, parameters, query state, lifecycle, guards, and nested content.
